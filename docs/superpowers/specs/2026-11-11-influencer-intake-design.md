## 1. 목적

마케팅은 GMV로 성과를 보고하지만 쿠폰·반품·광고비·수수료·물류비를 뺀 **실질 공헌이익**은 아무도 계산한 적이 없다. 그 결과 (a) 광고비 배분이 성과와 거꾸로 가고, (b) 실제 결정 기한과 승인 권한(현금 상황에 따라 바뀜)을 놓칠 수 있다.

이 시스템은 마케팅이 재무에 제안을 넘기는 시점에, 재무가 뒤에서 다시 모으던 정보(실질 성과, 기준점 비교, 현금·승인 판정)를 자동으로 붙이고, 결정이 기한 안에 처리되도록 상태와 기한을 관리한다.

### 사용자와 역할
| 역할 | 하는 일 | 근거 |
|---|---|---|
| 마케팅 담당 | 제안 요청 항목 입력 | 원본(회의록) |
| Masil 재무팀 | 현금·승인 판정 확인, 가정 검증 | 원본(회의록, covenant_terms) |
| 계약 담당 | 계약조건·기한 확인, 계약 원문 관련 확인 요청 담당 | W02 교육용 가정 (독립 부서 존재는 원본 미확정) |
| Masil 대표 | 대표 승인 경로의 결재 | 원본(approval_authority_policy) |
| CEO/이사회 | CEO 상신 경로의 결재 | 원본(approval_authority_policy) |

로그인·권한 관리는 만들지 않고 화면에서 역할 전환으로 모의한다.

### 성공 기준
1. 제안 한 건을 열면 "승인해도 되는가, 누가 **언제까지** 승인해야 하는가"가 한 화면에서 나온다.
2. 표 출력 단계(2단계)부터 마케팅·재무가 실제 업무에 쓸 수 있다.
3. 대회 필수 요건(아래 2장)을 시연으로 충족한다.
4. 모든 숫자에 근거 라벨이 붙고, 알려진 값은 가정 세트별 정답 기준 테스트로 재현된다.

## 4. 데이터와 가정

### 원본 사용
- 원본 폴더 `01_참가자_배포용/04_원본데이터`는 **읽기 전용**, 해시를 기록해 불변을 검증한다.
- 가공 데이터는 별도 폴더에 두고 원본 파일·행으로 추적 가능하게 한다.
- 입력 파일: `m_campaign_ms`, `m_influencer_ms`, `m_channel_ms`, `m_sku_ms`, `mkt_orders_ms`, `mkt_returns_ms`, `mkt_coupons_ms`, `mkt_ad_spend_ms`, `mkt_cost_master_ms`, `mkt_budget_plan_ms`, `fin_cash_daily_ms`, `fin_ar_aging_ms`, `fin_ap_aging_ms`, `sc_purchase_orders_ms`, `fin_cash_forecast_ms`, `ext_channel_benchmark`, `ext_industry_benchmark`, `inf001_exclusive_contract_notice.md`, 정책 문서(`approval_authority_policy`, `covenant_terms_ms`, `calculation_definitions`)
- 형식: UTF-8, 파이프(`|`) 구분, 첫 행 헤더, `NONE`은 해당 없음(0과 구분)
- 데이터 정합성 확인 결과: 모든 주문이 캠페인 기간 + 7일 안에 있고, 모든 주문의 SKU×채널이 원가 마스터에 있으며, 모든 광고비가 캠페인 기간 안에 있다.

### 원본 간 충돌과 적용 기준
| 충돌 | 적용 |
|---|---|
| `calculation_definitions` 1.4의 공헌이익 산식은 순매출(이미 환불 차감)에서 쿠폰과 반품환불을 다시 빼고 "정의 그대로" 적용하라고 함. A05 5절은 "동일 주문에 대해 쿠폰과 환불을 다시 차감하지 않는다". | **A05 우선**(A05 1절: 원본과 충돌 시 이번 지침 적용). 이중 차감하지 않는다. 원본 산식을 그대로 적용하면 음수 캠페인이 6건이 아니라 11건이 되므로, 이 차이를 회귀 테스트로 고정한다. |

### 데이터 규모 규칙
표본 계열(주문·쿠폰·반품·광고비·유입·예산기안)은 성과 판단에서 순위·비중·방향만 쓴다. 풀스케일 계열(재고·자금·손익)과 전속계약 28억 원은 표본 성과와 곱하거나 합산하지 않고 **나란히만** 표시한다. 엔진은 두 계열의 절대금액 연산을 차단한다. 기안 금액은 승인 한도 판정에만 쓰고(위 해석 가정), 현금 시뮬레이션에 금액을 더하지 않는다(날짜만 대조).

### 가정 (설정 파일 한 곳, 모든 값에 라벨 + 버전)
| 가정 | 기본값 | 대안 시나리오 |
|---|---|---|
| 주문당 판매 수량 | 1개 | 사용자 지정 |

| `settlement_date` 의미 | 집행 예정일 = 현금 유출일 | 확인 요청 대상 (자료에 정의 없음) |

비용 가정 민감도: 음수 실질 ROAS 6건은 수수료 기준(GMV/순매출)과 환불 시 원가 회수 여부를 어떻게 조합해도 같다(검수에서 확인).

### 이중 차감·이중 계상 방지
쿠폰은 GMV에 이미 반영되어 다시 빼지 않는다. 반품환불은 순매출에서 한 번만 뺀다. `influencer_fee_krw`는 `ad_cost_krw`에 포함되어 다시 더하지 않는다. `fin_ap_aging_ms`에서 `po_id`가 `sc_purchase_orders_ms`에 있는 행은 현금 유출에 넣지 않는다(발주 대금은 발주 파일로 한 번만).

### 현금 시뮬레이션의 한계
정의(`calculation_definitions` 1.2, `covenant_terms_ms`)대로 기준일 이후 **이미 잡힌 회수·지급 일정만** 합산한다. 기준일 이후 새로 발생할 매출의 회수는 들어가지 않으므로 보수적인 전망이다. 재무 공식 전망(`fin_cash_forecast_ms`)과의 차이는 화면에서 원인과 함께 표시한다(LC-0001 결제조건 반영 여부가 주 원인으로 보임 — [계산]).

## 5. 구성 요소와 규칙

### 5.1 아키텍처
```
[원본 CSV, 읽기 전용] → [적재·정제(별도 폴더)] → [계산 엔진] → [접수표 / 이슈 / 승인 경로] → 상태·결재 흐름 → 화면
                                                      ↑
                                            [업무 시계 · 가정 세트]
```

### 5.2 계산 엔진 모듈 (독립 모듈, 단위 테스트 가능)
| 모듈 | 입력 → 출력 |
|---|---|
| 실질 성과 | 주문·반품·광고비·원가마스터 → 캠페인·인플루언서별 공헌이익, 명목 ROAS, 실질 ROAS, 반품률(채널 보정) |
| 기준점 판정 | 성과표 + 기준값 → 이슈 목록(근거 포함) |
| 현금 시뮬레이션 | AR 회수예정 + 운영 AP + 재고 발주 지급 → 일별 잔액, 하회 구간, 공식 전망과의 차이 |
| 승인 경로 | 제안 건 + 하회 구간 → 경로 |
| 기한 관리 | 확정기한·집행 예정일 + 업무 시계 → 실효 결정 기한, 카운트다운, 알림 시점 |

계산 정의: 공헌이익 = 순매출(GMV − 반품환불) − 제품원가 − Marketing Spend − 채널수수료 − 출고 물류비 − 반품 물류비 (각 한 번씩, A05 5절). 명목 ROAS = GMV ÷ Marketing Spend, 실질 ROAS = 공헌이익 ÷ Marketing Spend. Marketing Spend = 해당 범위 `ad_cost_krw` 합. 분모 0이면 계산 불가로 처리. 비용 범위와 기간을 병기한다.

### 5.3 기준점 3층
- **A 원본 확정**: 승인 한도(건별 1천만 원, 기안 총액 1억 원, 전속계약 연 10억 원), covenant 최소현금 30억 원(매 영업일), 안전재고 4~6주, 귀속 7일, 계산 정의(A05 우선), 확정기한(7/17, 8/14, 9/11), 이사회(기준일 + 5일 = 2026-07-06)
- **B 외부 벤치마크(참고선, Masil 실적 아님)**: 반품률 업계 8%와 채널별(자사몰 8.5 / 마켓 9.0 / 대형파트너 12.0 / 대리점 11.0 / 라이브 13.0), 재구매율 22%와 채널별, 채널별 공헌이익률(정의 미기재라 직접 비교 금지)
- **C 제안 기본값(가정, 화면에서 조정 가능)**:

| 이슈 조건 | 정의와 기본값 |
|---|---|
| 손실 | 실질 ROAS < 0 → 이슈 |
| 반품률 | 캠페인 반품률(금액 기준)을 판매 채널 유형 벤치마크와 비교. 초과 시 주의, +3%p 초과 시 이슈 |
| 쿠폰 할인율 | 할인율 = 쿠폰 할인액 ÷ (GMV + 쿠폰 할인액). 전체 평균 초과 시 주의 |
| 배분 역전 | 인플루언서 10명을 요청 비중 순위와 실질 ROAS 순위로 각각 줄 세워, 요청 비중 상위 3위 안인데 실질 ROAS 하위 3위 안이면 이슈 |
| 표본 부족 | 캠페인 주문 수 100건 미만이면 판정 보류. 현재 모든 캠페인이 306건 이상이라 원본에서는 발생하지 않으므로 테스트용 사례로 검증 |
| 기한 알림 | 실효 결정 기한 D-14, D-7, D-3 (달력일) |

### 5.4 승인 경로 (위에서부터 적용, 먼저 걸리는 쪽이 우선)
| 순위 | 조건 | 경로 |
|---|---|---|
| 1 | 전속계약 연 10억 원 초과, 또는 현금 유출일이 하회 구간 안 (금액·종류 불문) | CEO/이사회 상신 |
| 2 | 건별 1천만 원 초과, 또는 기안 총액 1억 원 초과 | Masil 대표 승인 + 그룹 보고 |
| 3 | 그 외 | 마케팅 전결 |

- 현재 데이터에서는 기안 총액이 180,803,272원이라 3순위 해당 건이 없다.
- 현금 유출일은 집행 예정일(`settlement_date`)로 본다([가정]). 전속계약의 현금 유출일은 [미확인]이며, 미확인이어도 1순위(연 10억 원 초과)로 CEO 상신이다.
- 확정기한이 하회 구간보다 먼저 오는 건은 기한 전에 상신해야 한다(`covenant_terms_ms`).
- 에이전트는 경계를 넘는 결정을 자동 확정하지 않고 상신한다.

### 5.5 엔티티
- **업무 시계(BusinessClock)**: 업무 기준일(기본 2026-07-01), 현재 업무일. 시연에서 시계를 앞으로 진행해 알림·에스컬레이션을 발생시킨다. 실제 날짜와 분리한다.
- **제안 건(Case)**: 종류(기안 PLAN-xxx / 전속계약 갱신), 인플루언서, 요청액, 날짜(확정기한 / 집행 예정일 = 현금 유출일 / **실효 결정 기한**), 기안의 예상 GMV, 상태, 경로
  - 실효 결정 기한 = min(확정기한, 집행 예정일). 기안 25건 중 12건은 집행 예정일이 확정기한보다 빠르다(예: PLAN-007 집행 7/17·확정기한 8/14, PLAN-021 집행 7/21·확정기한 9/11).
  - 집행 예정일이 확정기한보다 빠른 건은 "확정 전 집행 예정" 이슈를 붙인다.
- **연결 그룹**: **같은 인플루언서의 모든 건**(기한 무관). 예: 혜인 PLAN-001·002·003 + 전속계약, Ava Glow PLAN-005·007·009. 한쪽만 부결하고 다른 쪽(특히 전속계약)을 방치하면 경고.
- **확인 요청(InfoRequest)**: 대상 건, 필요한 정보, 담당 역할, 기한(업무일), 상태(요청/회신/종결), 회신 원문, 구조화된 회신 값
- **이력(Event)**: 건, 업무일, 실제 시각, 행위자(역할), 행위, 근거 스냅샷, 가정 버전
- **가정 세트(AssumptionSet)**: 버전, 값, 라벨(확정/벤치마크/가정)

### 5.6 접수표 (한 건의 한 장)
| 구역 | 내용 | 누가 |
|---|---|---|
| 요청 | 캠페인·인플루언서, 요청액, 확정기한, 집행 예정일, 실효 결정 기한 | 마케팅 입력 |
| 기안의 주장 | 예상 GMV, 환산 명목 ROAS | 마케팅 입력 |
| 과거 실질 성과 | 실질 공헌이익·ROAS·반품률(채널 보정), 명목 순위 vs 실질 순위 | 자동 |
| 배분 점검 | 요청 비중 vs 기존 집행 비중 vs 실질 순위 | 자동 |
| 현금·승인 판정 | 현금 유출일이 하회 구간인지, 경로, 공식 전망과의 차이 | 자동, 재무 확인 |
| 상태 | 현재 상태, 기한 카운트다운, 이력, 연결 그룹 경고 | 시스템 |

## 6. 상태 흐름과 기한 가드 (필수 확장)

```
접수 → 자동 계산 → 재무 확인 → 경로 판정 → 상신 → 승인 / 거절 / 보류(확인 요청)
                                      ↑                         │
                                      └─ 회신 입력 시 재계산·재판정 ┘
승인 → 후속 작업 생성(통보 기록, 집행 일정)    거절 → 재상신 또는 종결
```

### 기한 가드 (W02 빈틈: "아니오 → 재검토 종료"인데 미통보면 자동 갱신)
- 종결되지 않은 모든 건은 **실효 결정 기한** D-14, D-7, D-3(달력일, 업무 시계 기준)에 알림이 생성된다.
- D-3 이후 보류 또는 미결정이면 상위 결재자에게 "결정 없이 기한이 지나면 자동 확정(또는 확정 전 집행)" 경고를 올리고 선택지 세 가지(조건 변경 통보, 해지 통보, 상신 후 승인)를 제시한다.
- CEO/이사회 상신 건은 기한 전 이사회(2026-07-06)를 표시한다.
- 보류에는 반드시 담당 역할과 기한이 있는 확인 요청이 붙는다. 담당·기한 없는 보류는 만들 수 없다.
- 업무 시계가 실효 결정 기한을 지나면 해당 건은 "기한 경과(자동 확정)" 상태가 되고 이력에 남는다.
- 모든 상태 변경은 이력에 기록한다.

### 연결 그룹 경고
기안만 부결하고 같은 인플루언서의 전속계약이 미결정이면 "기안만 부결, 계약은 자동 갱신" 경고를 표시한다.

## 10. AI 역할

계산과 판정은 코드가 확정한다(결정적). AI는 세 곳에서 쓴다.
1. **상신 근거 요약과 대안 비교 설명** 생성 (결재자가 읽는 한 장)
2. 부족 정보를 식별해 **확인 요청서 초안** 작성
3. 모의 회신(비정형 텍스트)을 해석해 **입력 필드 후보로 구조화** — 사람이 확인해야 반영

**숫자 대조 장치**: AI가 쓴 문장 속 숫자는 엔진 값과 대조하고, 불일치하면 반영하지 않고 표시한다.
AI는 승인·거절을 결정하지 않는다. AI 호출이 불가능한 환경이면 규칙 기반 템플릿으로 대체하고 "AI 미사용"으로 표시한다.
