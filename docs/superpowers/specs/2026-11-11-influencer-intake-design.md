# 인플루언서 제안 접수·판정 시스템 — 설계 명세

- 작성일: 2026-11-11
- 상태: 설계 승인됨(대화에서 1·2·3구간 승인). 이 명세의 검토·승인 후 구현 계획으로 넘어간다.
- 배경 정리: `pre.md` (근거 자료, 계산 결과, 가정 라벨 [확정]/[계산]/[가정]/[미확인] 정의 포함)
- 대상 업무: AX 인재전쟁 세계관 2번 "인플루언서 계약과 캠페인 집행" (W02)

---

## 1. 목적

마케팅은 GMV로 성과를 보고하지만 쿠폰·반품·광고비·수수료·물류비를 뺀 **실질 공헌이익**은 아무도 계산한 적이 없다. 그 결과 (a) 광고비 배분이 성과와 거꾸로 가고, (b) 확정기한(7/17)과 승인 권한(현금 상황에 따라 바뀜)을 놓칠 수 있다.

이 시스템은 마케팅이 재무에 제안을 넘기는 시점에, 재무가 뒤에서 다시 모으던 정보(실질 성과, 기준점 비교, 현금·승인 판정)를 자동으로 붙이고, 결정이 기한 안에 처리되도록 상태와 기한을 관리한다.

### 사용자
- 마케팅 담당: 제안 요청 항목 입력
- Masil 재무팀: 현금·승인 판정 확인, 가정 검증
- 결재자: Masil 대표, CEO/이사회 (승인·거절·보류 입력)

### 성공 기준
1. 제안 한 건을 열면 "승인해도 되는가, 누가 언제까지 승인해야 하는가"가 한 화면에서 나온다.
2. 표 출력 단계(2단계)부터 마케팅·재무가 실제 업무에 쓸 수 있다.
3. 대회 필수 요건(아래 2장)을 시연으로 충족한다.
4. 모든 숫자에 근거 라벨이 붙고, 알려진 값은 정답 기준 테스트로 재현된다.

## 2. 대회 필수 요건과 충족 방법 (A01·A04·A05)

| 요건 | 충족 방법 |
|---|---|
| 결정 입력 시 상태 실제 갱신 (BI만으로는 미완) | 승인/거절/보류 입력 → 상태·이력·확인 요청 작업 생성·갱신 (5장) |
| 시연 3건: 정상 / 변경 / 정보 부족·거절 | 9장 |
| 필수 확장 1개 (제안: 기한 가드 + 보류 후속 확인) | 6장 기한 가드 |
| 다른 부서 영향 1개 (제안: 재무 하회 구간이 승인 경로를 바꿈) | 5장 승인 경로 규칙 1순위 |
| 운영 중 AI 역할 | 10장 |
| 재현 방법 | 12장 산출물 |
| 실제 작동 / 모의 / 설계 단계 구분 | 11장 |
| 표본·풀스케일 절대금액 합산 금지 | 엔진에서 차단 (4장, 검증 8장) |

필수 확장과 다른 부서 영향의 선택은 **제안 상태**이며, 이 명세 승인 시 확정한다.

## 3. 범위

### 포함
- 계산 엔진(실질 성과, 기준점 판정, 현금 시뮬레이션, 승인 경로, 기한 관리)
- 제안 접수표 출력(CSV/엑셀)

- 시연 3건과 재현 절차, 제출 문서(A04) 초안

### 제외
- 실제 통보 발송, 실제 회사 시스템 연동
- 로그인·사용자 권한 관리 (화면에서 역할 전환으로 모의)
- 다른 세계관(1·3~8번) 구현
- 확장 후보 C(계약 구조 대안), D(귀속 중복 대사) — 설계 단계 추가 확장 목록으로만 기재

## 4. 데이터와 가정

### 원본 사용
- 원본 폴더 `01_참가자_배포용/04_원본데이터`는 **읽기 전용**, 해시를 기록해 불변을 검증한다.
- 가공 데이터는 별도 폴더에 두고 원본 파일·행으로 추적 가능하게 한다.
- 입력 파일: `m_campaign_ms`, `m_influencer_ms`, `m_channel_ms`, `m_sku_ms`, `mkt_orders_ms`, `mkt_returns_ms`, `mkt_coupons_ms`, `mkt_ad_spend_ms`, `mkt_cost_master_ms`, `mkt_budget_plan_ms`, `fin_cash_daily_ms`, `fin_ar_aging_ms`, `fin_ap_aging_ms`, `sc_purchase_orders_ms`, `fin_cash_forecast_ms`, `ext_channel_benchmark`, `ext_industry_benchmark`, `inf001_exclusive_contract_notice.md`, 정책 문서(`approval_authority_policy`, `covenant_terms_ms`, `calculation_definitions`)
- 형식: UTF-8, 파이프(`|`) 구분, 첫 행 헤더, `NONE`은 해당 없음(0과 구분)

### 데이터 규모 규칙
표본 계열(주문·쿠폰·반품·광고비·유입·예산기안)은 순위·비중·방향만 쓴다. 풀스케일 계열(재고·자금·손익)과 전속계약 28억 원은 표본 결과와 곱하거나 합산하지 않고 **나란히만** 표시한다. 엔진은 두 계열의 절대금액 연산을 차단한다.

### 가정 (설정 파일 한 곳, 모든 값에 라벨 + 버전)
| 가정 | 기본값 | 대안 시나리오 |
|---|---|---|
| 주문당 판매 수량 | 1개 | 사용자 지정 |
| 환불 시 원가·수수료 회수 | 회수 없음 | 회수 있음 |
| 반품 물류비 | 반품 1회당 1번 | - |
| 캠페인 귀속 | 주문의 `campaign_id` (last-click 7일) | - |
| 현금: 기준일 전 연체 AR | 기준일에 회수 | 제외 |
| 현금: 주말 일정 | 다음 영업일로 이월 | - |
| LC-0001 결제조건 | 90일(통보서 적용) | 45일(재무 공식 전망 가정) |
| 전속계약 위약금 | 잔여 고정 피의 50%, 월할 (계약 원문 미확인) | - |

### 이중 차감 방지 (A05)
쿠폰은 GMV에 이미 반영되어 다시 빼지 않는다. `influencer_fee_krw`는 `ad_cost_krw`에 포함되어 다시 더하지 않는다. 발주 대금은 `po_id`가 `sc_purchase_orders_ms`에 있는 AP 행을 현금 유출에 이중 계상하지 않는다.

## 5. 구성 요소와 규칙

### 5.1 아키텍처
```
[원본 CSV, 읽기 전용] → [적재·정제(별도 폴더)] → [계산 엔진] → [접수표 / 이슈 / 승인 경로] → 상태·결재 흐름 → 화면
```

### 5.2 계산 엔진 모듈 (독립 모듈, 단위 테스트 가능)
| 모듈 | 입력 → 출력 |
|---|---|
| 실질 성과 | 주문·반품·쿠폰·광고비·원가마스터 → 캠페인·인플루언서별 공헌이익, 명목 ROAS, 실질 ROAS, 반품률 |
| 기준점 판정 | 성과표 + 기준값 → 이슈 목록(근거 포함) |
| 현금 시뮬레이션 | AR 회수예정 + 운영 AP(`po_id=NONE`) + 재고 발주 지급 → 일별 잔액, 하회 구간 |
| 승인 경로 | 제안 건 + 하회 구간 → 경로 |
| 기한 관리 | 확정기한 → 카운트다운, 알림 시점 |

계산 정의는 `calculation_definitions.md`를 그대로 쓴다. 실질 ROAS = 공헌이익 ÷ Marketing Spend(`ad_cost_krw` 합), 분모 0이면 계산 불가로 처리.

### 5.3 기준점 3층
- **A 원본 확정**: 승인 한도(건별 1천만 원, 총액 1억 원, 전속계약 연 10억 원), covenant 최소현금 30억 원(매 영업일), 안전재고 4~6주, 귀속 7일, 고정 계산식, 확정기한(7/17, 8/14, 9/11)
- **B 외부 벤치마크(참고선, Masil 실적 아님)**: 반품률 업계 8%와 채널별(자사몰 8.5 / 마켓 9.0 / 대형파트너 12.0 / 대리점 11.0 / 라이브 13.0), 재구매율 22%와 채널별, 채널별 공헌이익률(정의 미기재라 직접 비교 금지)
- **C 제안 기본값(가정, 화면에서 조정 가능)**:

| 이슈 조건 | 기본값 |
|---|---|
| 실질 ROAS 0 미만 | 이슈(손실) |
| 반품률 | 해당 채널 벤치마크 초과 시 주의, +3%p 초과 시 이슈 |
| 쿠폰 할인율 | 전체 평균 초과 시 주의 |
| 요청 비중 상위인데 실질 순위 하위 | 이슈 |
| 표본 주문 수가 임계 미만 | 판정 보류 (임계값은 구현 단계에서 데이터 분포로 정해 가정 표시) |
| 기한 알림 | D-14, D-7, D-3 |

반품률은 반드시 **채널 유형 보정 후** 비교한다(혜인 캠페인은 반품률이 높은 채널에 몰려 있음).

### 5.4 승인 경로 (위에서부터 적용, 먼저 걸리는 쪽이 우선)
| 순위 | 조건 | 경로 |
|---|---|---|
| 1 | 전속계약 연 10억 원 초과, 또는 현금 유출일이 하회 구간 안 (금액 불문) | CEO/이사회 상신 |
| 2 | 건별 1천만 원 초과, 또는 기안 총액 1억 원 초과 | Masil 대표 승인 + 그룹 보고 |
| 3 | 그 외 | 마케팅 전결 |

- 현재 데이터에서는 기안 총액이 약 1.81억 원이라 3번 해당 건이 없다.
- 경로는 **현금 유출일**(집행 예정일 기준) 판정이며 확정기한과 구분한다.
- 에이전트는 경계를 넘는 결정을 자동 확정하지 않고 상신한다.

### 5.5 엔티티
- **제안 건(Case)**: 종류(기안 PLAN-xxx / 전속계약 갱신), 인플루언서, 요청액, 날짜 3개(확정기한 / 집행 예정일 / 현금 유출일), 기안의 예상 GMV, 상태, 경로, 연결 그룹 ID
- **연결 그룹**: 같은 인플루언서·같은 확정기한 건을 묶음. 한쪽만 부결하고 다른 쪽(특히 전속계약)을 방치하면 경고
- **확인 요청(InfoRequest)**: 대상 건, 필요한 정보, 담당자, 기한, 상태(요청/회신/종결), 회신 내용
- **이력(Event)**: 건, 시각, 행위자(역할), 행위, 근거 스냅샷, 가정 버전
- **가정 세트(AssumptionSet)**: 버전, 값, 라벨(확정/벤치마크/가정)

### 5.6 접수표 (한 건의 한 장)
| 구역 | 내용 | 누가 |
|---|---|---|
| 요청 | 캠페인·인플루언서, 요청액, 집행 예정일, 확정기한 | 마케팅 입력 |
| 기안의 주장 | 예상 GMV, 환산 명목 ROAS | 마케팅 입력 |
| 과거 실질 성과 | 실질 공헌이익·ROAS·반품률, 명목 순위 vs 실질 순위 | 자동 |
| 배분 점검 | 요청 비중 vs 기존 집행 비중 vs 실질 순위 | 자동 |
| 현금·승인 판정 | 현금 유출일이 하회 구간인지, 경로 | 자동, 재무 확인 |
| 상태 | 현재 상태, 기한 카운트다운, 이력 | 시스템 |

## 6. 상태 흐름과 기한 가드

```
접수 → 자동 계산 → 재무 확인 → 경로 판정 → 상신 → 승인 / 거절 / 보류(확인 요청)
                                      ↑                         │
                                      └─ 회신 입력 시 재계산·재판정 ┘
승인 → 후속 작업 생성(통보 기록, 집행 일정)    거절 → 재상신 또는 종결
```

### 기한 가드 (W02 빈틈: "아니오 → 재검토 종료"인데 미통보면 자동 갱신)
- 종결되지 않은 모든 건은 확정기한 D-14, D-7, D-3에 알림이 생성된다.
- D-3 이후 보류 또는 미결정이면 상위 결재자에게 "결정 없이 기한이 지나면 자동 확정" 경고를 올리고 선택지 세 가지(조건 변경 통보, 해지 통보, 상신 후 승인)를 제시한다.
- 보류에는 반드시 담당자와 기한이 있는 확인 요청이 붙는다. 담당자·기한 없는 보류는 만들 수 없다.
- 모든 상태 변경은 이력에 기록한다.

### 연결 그룹 경고
기안만 부결하고 같은 인플루언서의 전속계약이 미결정이면 "기안만 부결, 계약은 자동 갱신" 경고를 표시한다.

## 8. 검증

정답 기준 테스트(아래 값은 `pre.md` 4장의 계산 결과이며 [가정] 하에서만 성립):
- 실질 ROAS 음수 캠페인 6건: CMP-0001·0002·0003·0012·0013·0014
- 이 6건 요청액 합 77,397,264원 (총 180,803,272원의 약 42.8%)

- 경로 판정 단위 테스트(경계값: 1천만 원 / 1억 원 / 10억 원 / 구간 경계일)

- 표본·풀스케일 절대금액 합산 차단
- 원본 파일 해시 불변
- 가정 변경 시 결과가 달라지는 시나리오 테스트(변경 사례 시연의 근거)

## 9. 시연 3건

| 사례 | 입력 | 기대 결과 |
|---|---|---|
| 정상 | 기안 25건 + 혜인 전속계약 갱신 | 음수 6건 이슈. 하회 구간 안 12건과 전속계약은 CEO 상신, 나머지 13건은 대표 승인 + 그룹 보고. 혜인 연결 그룹 경고, 7/17 카운트다운 |
| 변경 | LC-0001을 45일로 변경 | 하회가 사라져 12건이 CEO에서 대표+그룹으로 재판정. 전속계약은 여전히 CEO. 성과 이슈는 현금과 무관해 유지(이유 표시) |
| 정보 부족·거절 | 고정 피 지급 일정 미확인 → 전속계약 보류 | 확인 요청 생성 → D-3 에스컬레이션 → 모의 회신(유리/불리/지연 세 가지) → 재계산·재판정. 또는 CEO 거절 → 재상신 |

모의 회신은 승인만이 아니라 거절·지연·불리한 내용을 포함한다(유리한 회신만으로 타당성을 입증하지 않음).

## 10. AI 역할

계산과 판정은 코드가 확정한다(결정적). AI는 두 곳에서 쓴다.
1. 부족 정보를 식별해 확인 요청서 초안 작성
2. 모의 회신(비정형 텍스트)을 해석해 입력 필드 후보로 구조화 — 사람이 확인해야 반영

AI는 승인·거절을 결정하지 않는다. 승인 경계를 넘는 결정은 상신한다.
