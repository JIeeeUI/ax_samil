확인 요청의 회신은 그 요청의 **담당 역할**(현금 유출일·지급 일정은 재무팀, 성과 피 조건은 계약 담당)이나 결재 역할(대표·CEO/이사회, 대신 입력)로 전환했을 때만 입력할 수 있고, 거절 후 재상신·종결은 마케팅 담당만 합니다(교육용 가정). 모든 모의 입력·회신은 화면과 이력에 "모의"로 표시됩니다. 업무 시계는 되돌릴 수 없으며, 다시 하려면 초기화합니다.

### 1차/2차 결재와 확장 알림 계획표 켜기 (선택)
`가정·기준값` 화면의 "결재·알림 설정"에서 "1차/2차 결재"를 켜면 CEO/이사회 건에 1차 대표 검토(상신/보류/반려)가 추가됩니다. 같은 곳에서 알림 계획표를 `extended`로 바꿀 수 있고, 기본은 꺼짐·`current`입니다. 이 기능은 켠 환경에서 1차 미결과 긴급(결정 기한 10일 이내)이 실제로 생길 때만 동작하며 위 시연 3건에는 포함되지 않습니다(테스트 `tests/app/two-stage.test.ts`로만 검증).

## 7. 재실행 전 초기화와 현재 제약
- 초기화: `가정·기준값` 화면의 "전체 초기화"(또는 `npm run demo`가 매번 수행). 로컬 메모리 DB라 개발 서버를 재시작해도 초기화됩니다.
- `npm start`(운영 모드)는 `DATABASE_URL`이 없으면 일부러 시작하지 않습니다. 로컬 확인은 `npm run dev`로 합니다.
- **AI**: 배포 주소에서 혜인 전속계약의 "AI로 다시 쓰기"가 AI 작성 문장을 만드는 것을 확인했습니다(Gemini 키는 사용자가 직접 등록, 응답에 최대 30초). 확인 요청서 초안·회신 구조화(Anthropic 키)의 실호출과 구글 서버가 바쁠 때(503)의 안내 화면은 실제로 확인하지 못했고 가짜 응답으로만 테스트했습니다.
- **PostgreSQL 접속**: 배포 주소는 앱 DB(PostgreSQL)에 연결돼 있고, 결재·보류·회신·시계 진행·재상신 결과가 저장되는 것을 화면에서 확인했습니다. 로컬 테스트는 PGlite(Postgres 호환)로 합니다.
