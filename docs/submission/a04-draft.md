## 1. 문제와 전문성 확장 요약
| 항목 | 내용 |
|---|---|
| 결과물 이름 | 인플루언서 제안 **상신 전 점검** 도구 (W02 "인플루언서 계약과 캠페인 집행"). 업무 전체를 자동화하지 않고 그중 한 구간 "상신 전 점검"만 자동화한다 |
| 선택한 사용자·의사결정 | **마케팅 실무자**가 기안 25건과 혜인 전속계약 갱신을 상신하기 전에, 이 건을 **누가·언제까지 승인해야 하고 근거가 무엇이며 빠진 정보가 있는지** 점검한다. 기존 결재·소통은 그대로 두고, 시스템은 계산·판정·초안까지, **상신·승인은 사람**이 한다 |
| 현재의 어려움 | 마케팅은 GMV로 보고하고 쿠폰·반품·광고비·수수료·물류비를 뺀 실질 공헌이익은 아무도 계산하지 않았다(정보 공백). 현금 상황에 따라 승인 권한이 바뀌고, 집행 예정일이 확정기한보다 빠른 12건은 실제 결정 기한을 놓치기 쉽다(판단 지연). 상신은 되돌릴 수 없어 상신 전에 빠진 것을 찾아야 한다 |
| 기업 운영 안에서의 연결 | 입력: 마케팅 기안·전속계약 통보서·재무 자금 자료. 시스템(점검 구간): 실질 성과·반품 원인 분리 보기·현금 하회 구간·공식 전망과의 차이·승인 경로·실효 결정 기한 계산, 점검 결과 네 줄과 라벨(확인 대기/상신 준비 완료/상신함). 앞뒤 정보: 마케팅 → 재무(현금·covenant) → 대표/CEO(결재, 사람) → 계약 담당. 결재 이후 기능은 구현됨·시연 제외 |
| 주업무의 시작과 종료 | 시작: 기안·계약 접수 → 자동 계산·이슈 → **점검 결과** → 빠진 정보면 확인 요청(확인 대기) → 회신 후 재점검 → 재무가 같은 점검표로 금액 확인(재무 확인 대기 → 상신 준비 완료) → 사람이 확인 후 상신(상신함). 종료(이 도구의 범위): 상신. 이후 승인/거절/보류·기한 경과 기록은 구현됐지만 시연에서 제외 |
| 본인의 관심·전문성 | [사용자 작성] |
| 필수 전문성 확장 | **확장 ①: 반품 원인 분리 보기.** `returnAttribution: 'all'(기본) | 'demandOnly'`. 오배송·불량 반품의 환불액과 반품 물류비를 인플루언서 성과에서 제외한 평가용 보기(회사 손익은 그대로, [가정: 오배송·불량은 인플루언서 책임이 아니라는 해석]). 혜인 −0.20→약 −0.11, Ava Glow −0.21→약 −0.13(둘 다 여전히 손실), 하위 3명 순서(Ava Glow, 혜인, Lila SEA) 유지, 운영·품질 원인 반품 878/1,719건(약 51%). 위치: `src/engine/performance.ts`. 증거: `tests/engine/return-attribution.test.ts`, 시연 `demo -- check`(변경) |
| 영향받는 다른 부서의 목표·제약 | 재무: covenant 최소 현금 30억 원(매 영업일) 유지. 하회 예상 구간(기본 가정 2026-07-21~08-21)에 현금이 나가는 신규 약정은 금액·종류 불문 CEO/이사회 승인. 재무 공식 전망(최저 약 54.7억, 하회 없음)과 재계산(최저 약 16.5억, 하회)이 다름 |
| 다른 부서 영향의 실제 반영 | ① 재무 covenant: 하회 구간 안 기안 12건(99,550,557원)이 대표 경로에서 CEO/이사회 상신으로 바뀐다(`src/engine/cash.ts`, `src/engine/routing.ts`, `tests/engine/routing.test.ts`). ② 공식 전망과의 차이 표시: 점검 화면에 두 전망을 나란히 보이고 "재무 확인 필요"로 표시, 확인된 사실은 "LC-0001을 45일로 가정하면 하회가 사라진다(재계산 결과)"뿐이며 원인은 단정하지 않는다(`src/engine/cashGap.ts`, `tests/engine/cash-gap.test.ts`). 증거: 시연 "정상"·"변경" |
| 확인할 개선 효과 | 확인됨: 실질 ROAS 음수 6건 식별, 확정 전 집행 12건 표시, 승인 경로·기한 자동 판정, 반품 원인 분리 후에도 혜인·Ava Glow는 손실. **금액 절감 효과는 산정하지 않음**(표본 계열 금액에 풀스케일 금액을 곱하지 않기 때문). 비교 방법: 가정 세트 5종별 정답 기준 테스트 |

## 2. 업무모델과 데이터 설명
| 구분 | 내용 |
|---|---|
| 핵심 객체와 의미 | 제안 건(기안 PLAN-xxx / 전속계약), 인플루언서, 캠페인, 업무 시계, 확인 요청, 이력, 가정 세트, 하회 구간 |
| 핵심 관계와 연결 기준 | 주문의 `campaign_id`(last-click 7일)로 성과를 귀속. 같은 인플루언서의 모든 건을 연결 그룹으로 묶음(예: 혜인 PLAN-001·002·003 + 전속계약) |
| 상태·적용 시점·담당자·승인권한 | 상태: 재무 확인 대기 → 경로 판정됨 → 상신됨 → 승인/거절/보류 → 기한 경과/종결. 경로(위에서부터 적용): ① 전속계약 연 10억 원 초과 또는 현금 유출일이 하회 구간 안 → CEO/이사회 ② 건별 1천만 원 또는 기안 총액 1억 원 초과 → Masil 대표 + 그룹 보고 ③ 그 외 마케팅 전결. 결재 역할이 아닌 사람은 결정할 수 없음. 확인 요청 담당은 정보를 가진 부서, 회신 입력은 담당 + 결재 역할, 거절 후 재상신·종결은 마케팅 [교육용 가정, 원본이 보류 이후 담당을 정하지 않음] |
| 판단에 사용하는 규칙과 제약 | 공헌이익은 A05 기준(쿠폰·환불 이중 차감 없음). 표본 계열과 풀스케일 계열 절대금액 합산 차단. 가정은 모두 라벨(확정/벤치마크/가정)과 버전 표시 |
| 업무모델이 조회·계산·판단·승인·후속 작업을 연결하는 위치 | `src/app/service.ts`가 엔진(`src/engine/*`)·상태 규칙(`src/workflow/*`)·저장소(`src/store/*`)를 묶고, 화면(`app/*`)은 서비스만 호출 |
| 제공 BPMN에서 바꾼 것 | 해당 없음/[사용자 확인]. 원본의 승인 권한과 제약은 바꾸지 않았고, 에이전트는 경계를 넘는 결정을 자동 확정하지 않는다 |

## 3. 대표 실행 사례

| 정보 부족·거절 | 지급 일정 미확인 → 전속계약 보류 | 재무에 확인 요청(기한 있음) → 시계 7/14에 D-3 에스컬레이션 → 유리/불리/지연 회신 각각 재판정(유리 9/30: 하회 구간 밖, 불리 8/10: 안 — 28억은 어느 쪽이든 CEO/이사회) → CEO 거절 후 재상신. 기안 PLAN-001만 거절하면 "기안만 부결, 계약은 자동 갱신" 경고 | `npm run demo -- shortage` |
| **상신 전 점검 (주 시연)** | 업무 기준일 2026-07-01, 시계 진행 없음 | 정상: PLAN-019(초혜핏 CMP-0005, 집행 9/14, 하회 구간 밖, 실질 ROAS 2.97) 점검 통과 → 재무 확인 대기 → 재무 확인 → 상신 준비 완료 → 사람이 상신(대표 승인+그룹 보고, 총액 1억 초과). 변경: 혜인 PLAN-001과 같은 날 마감 전속계약을 함께 보고 가정을 바꿔 재점검 — 반품 원인 분리·연체 매출채권 제외는 결론 유지(여전히 손실, 하회는 8/28까지), LC-0001 45일은 하회가 사라져 PLAN-001이 CEO→대표+그룹으로 바뀜(전속계약 28억은 그대로 CEO/이사회). 정보 부족: 전속계약 28억 지급일 미확인 → 확인 대기 → 재무 확인 요청 → 모의 회신(8/10 하회 구간 안/9/30 밖) → 재점검(재무 확인 전이면 재무 확인 대기, 확인 후면 상신 준비 완료; 이 시연은 확인 후 회신). **28억은 어느 쪽이든 CEO/이사회**이고 회신이 바꾸는 것은 하회 구간 해당 여부와 상태다 | `npm run demo -- check`, `tests/demo/scenarios.test.ts` |

- 선택 설정(교육용 가정): `가정·기준값`에서 "1차/2차 결재"를 켜면 CEO/이사회 건에 대표 검토(1차)가 추가된다. 방법은 reproduce.md의 "1차/2차 결재와 확장 알림 계획표 켜기", 켠 상태의 동작은 시연이 아니라 합성 시계·합성 건 테스트(`tests/app/two-stage.test.ts`)로만 증명했고 기본 시연 3건에는 포함하지 않는다.
- 운영 중 AI의 역할: 상신 근거 요약, 확인 요청서 초안, 모의 회신 구조화(후보일 뿐 사람이 확인해야 반영). AI 문장 속 숫자·날짜는 엔진 값과 대조해 불일치하면 쓰지 않는다. 키가 없으면 템플릿(화면에 "AI 미사용"). 위치: `src/ai/*`. **실제 AI 호출은 키가 없어 검증하지 못했다.**
- 예상 효과의 산정과 가정: 금액 효과는 산정하지 않는다(표본·풀스케일 혼합 금지). 비용 가정 민감도: 음수 실질 ROAS 6건은 수수료 기준·환불 시 원가 회수 가정 조합에 관계없이 같다.
- 확인된 효과 / 모의·추정: 확인됨 — 계산·판정·상태 변경·알림. 모의 — CEO·대표 결정, 담당 부서(재무·계약 담당)·에이전시 회신, 통보 발송.
- 필수 확장이 쓰인 지점: 점검 결과 ③(실질 ROAS와 반품 원인 분리 보기)와 시연 "변경"의 가정 전환. 다른 부서 영향 반영 지점: 점검 결과의 승인 경로(하회 구간 → CEO/이사회)와 공식 전망 차이 표시.

## 5. 실행·재현 방법
`docs/submission/reproduce.md`를 따른다. 요약: `npm ci` → `npm test`(218개) → `npm run demo -- check`(주 시연) 또는 `npm run demo -- all`(결재 이후 3건) → `npm run dev` 화면에서 역할 전환 → "전체 초기화"로 재실행.
