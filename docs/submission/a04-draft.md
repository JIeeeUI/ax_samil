# A04 제출 문서 초안 — 인플루언서 제안 상신 전 점검 도구

> 초안입니다. "본인의 관심·전문성" 칸은 사용자의 답변을 정리해 채웠고, 사용자 확인이 필요합니다(칸 끝의 `[사용자 확인 필요]` 참고). `[별도 운영 공지 확인]`은 제출 형식·제출처·일정입니다. 근거 문서: `docs/superpowers/specs/2026-11-11-influencer-intake-design.md`(명세), `pre.md`(배경 정리), `docs/submission/reproduce.md`(재현 절차).

## 1. 문제와 전문성 확장 요약
| 항목 | 내용 |
|---|---|
| 결과물 이름 | 인플루언서 제안 **상신 전 점검** 도구 (W02 "인플루언서 계약과 캠페인 집행"). 업무 전체를 자동화하지 않고 그중 한 구간 "상신 전 점검"만 자동화한다 |
| 선택한 사용자·의사결정 | **마케팅 실무자**가 기안 25건과 혜인 전속계약 갱신을 상신하기 전에, 이 건을 **누가·언제까지 승인해야 하고 근거가 무엇이며 빠진 정보가 있는지** 점검한다. 기존 결재·소통은 그대로 두고, 시스템은 계산·판정·초안까지, **상신·승인은 사람**이 한다 |
| 현재의 어려움 | 마케팅은 GMV로 보고하고 쿠폰·반품·광고비·수수료·물류비를 뺀 실질 공헌이익은 아무도 계산하지 않았다(정보 공백). 현금 상황에 따라 승인 권한이 바뀌고, 집행 예정일이 확정기한보다 빠른 12건은 실제 결정 기한을 놓치기 쉽다(판단 지연). 상신은 되돌릴 수 없어 상신 전에 빠진 것을 찾아야 한다 |
| 기업 운영 안에서의 연결 | 입력: 마케팅 기안·전속계약 통보서·재무 자금 자료. 시스템(점검 구간): 실질 성과·반품 원인 분리 보기·현금 하회 구간·공식 전망과의 차이·승인 경로·실효 결정 기한 계산, 점검 결과 네 줄과 라벨(확인 대기/상신 준비 완료/상신함). 앞뒤 정보: 마케팅 → 재무(현금·covenant) → 대표/CEO(결재, 사람) → 계약 담당. 결재 이후 기능은 구현됨·시연 제외 |
| 주업무의 시작과 종료 | 시작: 기안·계약 접수 → 자동 계산·이슈 → **점검 결과** → 빠진 정보면 확인 요청(확인 대기) → 회신 후 재점검 → 재무가 같은 점검표로 금액 확인(재무 확인 대기 → 상신 준비 완료) → 사람이 확인 후 상신(상신함). 종료(이 도구의 범위): 상신. 이후 승인/거절/보류·기한 경과 기록은 구현됐지만 시연에서 제외 |
| 본인의 관심·전문성 | **관심**: 인플루언서의 활동과 라이브, X·스레드 같은 SNS의 반응이 캠페인 성과에 바로 영향을 준다는 점이 흥미로워 이 업무를 골랐다.<br>**경험**: 졸업 후 MD로 1년 정도 일했고, 아르바이트를 포함해 총 3년 정도 회사 생활을 하며 여러 사람의 업무 이야기를 보고 들었다. 특정 자격이나 기준이 아니라 이 경험을 바탕으로 판단했다.<br>**적용한 관점**<br>① 성과 보고와 실제로 남는 돈의 차이: 음식점으로 비유하면 매출에서 재료비·인건비를 빼야 마진을 알 수 있는데, 마케팅 성과 보고(GMV)는 쿠폰·반품·광고비를 빼지 않아 이상하다고 보았다. 그래서 이를 뺀 실질 공헌이익으로 판단하게 했다.<br>② 마감일이 지나면 자동 갱신되는 계약: 담당자가 확인하지 않으면 계약이 이어지고, 그것도 성과가 손실인 인플루언서와의 갱신이라는 점이 가장 이상했다. 그래서 실효 결정 기한과 "되돌릴 수 없음"을 점검 결과에 항상 보이게 했다.<br>③ 반품 원인 분리: 제품을 만들어 파는 곳에서는 어떤 제품도 모든 고객의 마음에 들 수 없어 반품이 어느 정도 생긴다. 그런데 오배송·불량처럼 인플루언서가 책임질 수 없는 반품(운영·품질 원인 878/1,719건, 약 51%)까지 인플루언서의 성과 손실로 보면 평가가 공정하지 않다고 보았다. 그래서 그런 반품을 뺀 "평가용 보기"를 따로 두고 가정으로 표시했다(결론은 바뀌지 않음: 혜인 −0.20→약 −0.11, Ava Glow −0.21→약 −0.13).<br>④ 작게 시작하는 자동화: 처음에는 업무 전체를 자동화하려 했으나 멘토 피드백을 받고 바꿨다. 첫 결과물에서 실수가 하나라도 나면 회사가 손해를 볼 수 있고 바쁜 실무자의 신뢰도 잃어 쓰이지 않는다. 그래서 가장 실수가 잦은 "상신 전 점검" 한 구간만 맡기고 상신·결정은 사람이 하게 했다. 자동화는 모든 사람이 쉽게 쓰고 시간을 줄여야 의미가 있으므로 화면과 설계를 쉬운 말과 단순한 구조로 만들었다.<br>⑤ 직접 확인하는 작업 방식(작업 기록 기준): AI의 결과를 그대로 받지 않고 확인하게 했다. 흐름이 이해되지 않을 때는 원본 자료(위임전결 규정, 계약 통보서, BPMN)를 다시 읽게 해 근거를 확인하고, 원본에 없는 부분은 "교육용 가정"으로 표시하게 했다. 원본 자료 폴더는 수정하지 않게 했고, 작업 보고는 직접 확인한 뒤에 말하게 했다. 처리 기록에서 누가 누구에게 넘겼는지 보이지 않는 점을 짚어 보낸 사람·받는 부서·시각을 추가하게 했다. 배포 주소에서는 결재·보류·회신·재상신을 직접 눌러 상태가 저장되는지 확인했다.<br>**배운 점**: 자동화는 업무 전체의 흐름과 해당 업무의 기초 지식을 알아야 만들 수 있다. 처음에는 업무를 몰라 답답했고, AI에게 계속 질문하며 일의 흐름을 파악했다.<br>[사용자 확인 필요: 경험·관심은 사용자 답변을 정리한 것이고, ③의 이유와 ⑤는 작업 기록을 바탕으로 AI가 문장을 쓴 것] |
| 필수 전문성 확장 | **확장 ①: 반품 원인 분리 보기.** `returnAttribution: 'all'(기본) | 'demandOnly'`. 오배송·불량 반품의 환불액과 반품 물류비를 인플루언서 성과에서 제외한 평가용 보기(회사 손익은 그대로, [가정: 오배송·불량은 인플루언서 책임이 아니라는 해석]). 혜인 −0.20→약 −0.11, Ava Glow −0.21→약 −0.13(둘 다 여전히 손실), 하위 3명 순서(Ava Glow, 혜인, Lila SEA) 유지, 운영·품질 원인 반품 878/1,719건(약 51%). 위치: `src/engine/performance.ts`. 증거: `tests/engine/return-attribution.test.ts`, 시연 `demo -- check`(변경) |
| 영향받는 다른 부서의 목표·제약 | 재무: covenant 최소 현금 30억 원(매 영업일) 유지. 하회 예상 구간(기본 가정 2026-07-21~08-21)에 현금이 나가는 신규 약정은 금액·종류 불문 CEO/이사회 승인. 재무 공식 전망(최저 약 546,888만 원 ≈ 54.7억, 하회 없음)과 재계산(최저 약 164,784만 원 ≈ 16.5억, 하회)이 다름 |
| 다른 부서 영향의 실제 반영 | ① 재무 covenant: 하회 구간 안 기안 12건(99,550,557원)이 대표 경로에서 CEO/이사회 상신으로 바뀐다(`src/engine/cash.ts`, `src/engine/routing.ts`, `tests/engine/routing.test.ts`). ② 공식 전망과의 차이 표시: 점검 화면에 두 전망을 나란히 보이고 "재무 확인 필요"로 표시, 확인된 사실은 "LC-0001을 45일로 가정하면 하회가 사라진다(재계산 결과)"뿐이며 원인은 단정하지 않는다(`src/engine/cashGap.ts`, `tests/engine/cash-gap.test.ts`). 증거: 시연 "정상"·"변경" |
| 확인할 개선 효과 | 확인됨: 실질 ROAS 음수 6건 식별, 확정 전 집행 12건 표시, 승인 경로·기한 자동 판정, 반품 원인 분리 후에도 혜인·Ava Glow는 손실. **금액 절감 효과는 산정하지 않음**(표본 계열 금액에 풀스케일 금액을 곱하지 않기 때문). 비교 방법: 가정 세트 5종별 정답 기준 테스트 |

### 설계 원칙 (기획 논의 반영, 사용자 확인 필요)
| 원칙 | 이 도구에서의 모습 |
|---|---|
| 실무자가 쓰는 도구 | 쓰는 사람은 마케팅·재무·계약 담당 실무자다. 일을 처음 맡은 사람도 별도 학습 없이 쓰도록 화면 문구를 쉬운 말로 쓴다(용어를 풀어 쓰고, 주의 항목은 "주의할 점 N가지"와 중요도 상·중·하로 보인다). 대표·CEO/이사회의 결정은 기존 결재 방식 그대로이며, 도구 안의 결재자 역할 전환은 시연을 위한 모의 입력이다(로그인·권한 관리 없음) |
| 두뇌 노동을 대신하고 결론만 보인다 | 규정집을 찾고 수식을 계산하던 판단(승인 경로, 실효 결정 기한, 실질 공헌이익, 현금 하회 구간 해당 여부)을 엔진이 처리하고, 화면은 숫자 나열이 아니라 "누가·언제까지 승인해야 하는가 / 근거 / 빠진 정보와 물어볼 곳"을 점검 결과로 보인다 |
| 작은 자동화, 사람의 통제권 | 업무 전체가 아니라 "상신 전 점검" 한 구간만 자동화한다. 기존 결재·부서 간 소통은 그대로 두고, 시스템은 상신을 대신하거나 막지 않는다. 상신·승인·보류·거절은 사람이 하며, 상신은 되돌릴 수 없다는 확인 단계를 한 번 더 둔다. AI는 문장 초안·구조화만 하고 결정하지 않는다 |

## 2. 업무모델과 데이터 설명
| 구분 | 내용 |
|---|---|
| 핵심 객체와 의미 | 제안 건(기안 PLAN-xxx / 전속계약), 인플루언서, 캠페인, 업무 시계, 확인 요청, 이력, 가정 세트, 하회 구간 |
| 핵심 관계와 연결 기준 | 주문의 `campaign_id`(last-click 7일)로 성과를 귀속. 같은 인플루언서의 모든 건을 연결 그룹으로 묶음(예: 혜인 PLAN-001·002·003 + 전속계약) |
| 상태·적용 시점·담당자·승인권한 | 상태: 재무 확인 대기 → 경로 판정됨 → 상신됨 → 승인/거절/보류 → 기한 경과/종결. 경로(위에서부터 적용): ① 전속계약 연 10억 원 초과 또는 현금 유출일이 하회 구간 안 → CEO/이사회 ② 건별 1천만 원 또는 기안 총액 1억 원 초과 → Masil 대표 + 그룹 보고 ③ 그 외 마케팅 전결. 결재 역할이 아닌 사람은 결정할 수 없음. 확인 요청 담당은 정보를 가진 부서, 회신 입력은 담당 + 결재 역할, 거절 후 재상신·종결은 마케팅 [교육용 가정, 원본이 보류 이후 담당을 정하지 않음] |
| 판단에 사용하는 규칙과 제약 | 공헌이익은 A05 기준(쿠폰·환불 이중 차감 없음). 표본 계열과 풀스케일 계열 절대금액 합산 차단. 가정은 모두 라벨(확정/벤치마크/가정)과 버전 표시 |
| 업무모델이 조회·계산·판단·승인·후속 작업을 연결하는 위치 | `src/app/service.ts`가 엔진(`src/engine/*`)·상태 규칙(`src/workflow/*`)·저장소(`src/store/*`)를 묶고, 화면(`app/*`)은 서비스만 호출 |
| 제공 BPMN에서 바꾼 것 | 없음. 제공 BPMN을 재설계하지 않았다. 원본의 역할·순서·승인 권한·제약은 그대로이고, 그 위에서 "상신 전 점검" 한 구간만 보조한다. 에이전트는 경계를 넘는 결정을 자동 확정하지 않는다. 원본이 정하지 않은 보류·거절 이후의 담당 배정 등은 BPMN을 바꾼 것이 아니라 "교육용 가정"으로 따로 표시했다 |

## 3. 대표 실행 사례
